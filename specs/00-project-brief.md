# Project Brief：图书管理系统

## 1. 项目背景

本项目是《软件设计与体系结构》课程实验项目（实验一 + 实验二），用于训练需求分析、UML 建模、架构设计、数据库设计、详细设计和代码实现能力。

与传统的"UML 建模 + 代码实现"不同，本实验采用 **Spec-Driven（规格驱动）+ Agent 辅助**的开发范式：由 AI Agent 起草规格与代码初稿，由人负责审查、修订和拍板。实验的考核重点不是"画了多少图、写了多少行代码"，而是**能否用规范指挥 Agent，并对 Agent 的产出承担责任**。

## 2. 项目目标

开发一个可运行、可测试的图书管理系统，支持读者注册、借阅证管理、图书借阅、图书归还、借阅查询、图书预约、系统维护和超期罚款。

系统需满足以下工程要求：

- 后端采用**分层架构**（表现层 / 应用服务层 / 领域层 / 基础设施层），业务规则集中在领域层与应用服务层，不得写入 Controller。
- 前端与后端**分离**，通过 REST API 通信。
- 核心用例具备**自动化测试**，覆盖正常路径、业务规则失败路径和权限失败路径。
- 全流程遵循 `specs/constitution.md` 定义的开发宪法。

## 3. 目标用户

| 参与者 | 说明 |
|---|---|
| 读者（Reader） | 抽象参与者，代表所有具备借阅资格的读者 |
| 学生读者（StudentReader） | 读者的子类型，含本科生、研究生、博士生、专科生 |
| 教师读者（TeacherReader） | 读者的子类型 |
| 图书管理员（Librarian） | 代理读者完成借书、还书、查询借阅信息 |
| 系统管理员（SystemAdmin） | 负责借阅证、管理员、图书、标题信息、借阅规则和罚款规则的维护 |

## 4. 主要业务

- 注册账号
- 办理借阅证 / 删除借阅证
- 借阅图书（由图书管理员代理）
- 归还图书（由图书管理员代理）
- 查询借阅信息
- 预约图书
- 查询图书
- 维护图书标题信息
- 维护馆藏副本
- 维护图书管理员
- 维护借阅规则和罚款规则
- 计算超期罚款

## 5. 读者类型

| 读者类型 | 说明 |
|---|---|
| 本科生（UNDERGRADUATE） | 学生读者 |
| 研究生（GRADUATE） | 学生读者 |

不同读者类型具有不同的**最大借阅数量**和**借阅期限**。具体数值见 `specs/02-requirements.md` 业务规则章节。

| 借出物类型 | 说明 |
|---|---|

## 7. 技术要求

### 7.1 技术栈

| 层次 | 技术选型 |
|---|---|
| 后端语言 | Python 3.10+ |
| 后端框架 | FastAPI |
| ORM | SQLAlchemy |
| 数据库 | SQLite |
| 数据校验 | Pydantic |
| 后端测试 | pytest + httpx |
| 前端语言 | TypeScript |
| 前端技术 | HTML / CSS / TypeScript（允许使用 React） |
| 建模工具 | PlantUML 或 Mermaid（文本格式，纳入 Git 管理） |
| 版本控制 | Git |

### 7.2 建模与文档要求

- 使用 UML 表达分析和设计结果。
- 所有 UML 图必须使用 **PlantUML 或 Mermaid 文本格式**保存，纳入 Git 管理，不得只提交图片。
- 规格文档使用**中文**书写，代码标识符使用**英文**。
- 所有 Agent 生成内容必须经人工审查后方可作为实现依据。

### 7.3 交付要求

- 最终需交付可运行的代码和通过的自动化测试。

## 8. 暂不实现

以下功能明确不在本次实验范围内，任何规格文档和代码均不得引入：

- 支付系统真实扣款
- 图书条码扫描硬件
- 复杂全文检索
- 多校区馆藏调拨
- 微信或统一身份认证登录
- 真实密码认证（第一阶段不做登录认证，操作人身份通过请求中的 ID 参数标识）

## 9. 非目标

- 不做高并发、分布式部署设计。
- 不做生产级安全加固（不涉及真实用户数据）。
- 不追求界面美观度，前端以"能演示核心用例"为目标。
