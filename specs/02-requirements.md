## 1. 项目概述

### 1.1 项目目标

开发一个可运行、可测试的图书管理系统，支持读者注册、借阅证管理、图书借阅、图书归还、借阅查询、图书预约、系统维护和超期罚款。

系统须满足以下工程约束：

- 后端采用分层架构（表现层 / 应用服务层 / 领域层 / 基础设施层），业务规则集中在领域层与应用服务层（见 `constitution.md` 第五条、第六条）。
- 前端与后端分离，通过 REST API 通信。
- 核心用例具备自动化测试，覆盖正常路径、业务规则失败路径与权限失败路径。

### 1.2 参与者

| 参与者 | 类型 | 职责概述 |
|---|---|---|
| **读者 Reader** | 抽象参与者 | 查询图书、预约图书、查看本人借阅状态 |
| **学生读者 StudentReader** | Reader 的子类型 | 含专科生、本科生、研究生、博士生 |
| **教师读者 TeacherReader** | Reader 的子类型 | 借阅额度最高的读者类型 |
| **图书管理员 Librarian** | 具体参与者 | 代理读者办理借书、还书，查询借阅信息，收缴罚款 |
| **系统管理员 SystemAdmin** | 具体参与者 | 维护借阅证、账号、书目、馆藏、借阅规则与罚款规则 |

**继承关系**：`StudentReader` 与 `TeacherReader` 泛化自 `Reader`。

### 1.3 系统边界

**系统负责**：账号与认证、借阅证管理、书目与馆藏管理、借阅流通（借出/归还/续借）、预约管理、罚款计算与记录、规则维护、查询与统计。

**系统不负责**（依据 `00-project-brief.md` §8）：

- 支付系统真实扣款
- 图书条码扫描硬件
- 复杂全文检索
- 多校区馆藏调拨
- 微信或统一身份认证登录
- 高并发、分布式部署
- 生产级安全加固

## 2. 功能需求（Functional Requirements）

> 共 29 条功能需求。每条含描述与可验证的验收标准。
> 编号规则：`FR-XXX`，按模块分组。

### 2.1 认证与账号模块

#### FR-001 用户登录

**描述**：系统应支持读者、图书管理员、系统管理员通过用户名和密码登录，登录成功后签发 JWT Token。

**验收标准**：

1. 输入正确的用户名与密码，返回 JWT Token 与用户角色，HTTP 200。
2. 用户名不存在或密码错误，返回 `UNAUTHORIZED`，HTTP 401，提示信息统一为"用户名或密码错误"（不区分具体原因）。
3. Token 有效期为 24 小时，过期后请求受保护接口返回 `UNAUTHORIZED`，HTTP 401。
4. 密码以 bcrypt 哈希存储，数据库中不可见明文。

**关联决策**：D-01、D-01a

---

#### FR-002 读者注册账号

**描述**：系统应支持读者自助注册账号，填写用户名、密码、姓名、院系、读者类型。注册后账号立即可用，无需审核。

**验收标准**：

1. 提交合法的用户名（3-32 位，仅字母/数字/下划线）、密码（6-24 位）、姓名、院系、读者类型，注册成功，HTTP 201。
2. 用户名已存在，返回 409 冲突。
3. 密码长度不足 6 位或超过 24 位，返回 422 参数错误。
4. 读者类型不在允许枚举内，返回 422 参数错误。
5. 注册成功后即可登录，但**在办理借阅证前不具备借阅资格**（见 BR-011）。

**关联决策**：D-11、D-01a

---

#### FR-003 添加图书管理员账号

**描述**：系统应支持系统管理员创建和软删除图书管理员账号。

**验收标准**：

1. 系统管理员创建图书管理员账号，需提供用户名、密码、姓名，创建成功。
2. 图书管理员或读者调用此接口，返回 `PERMISSION_DENIED`，HTTP 403。
3. 用户名重复，返回 409 冲突。
4. 删除图书管理员为**软删除**，该账号不可再登录，但借阅历史中的 `librarian_id` 仍可追溯。

**关联决策**：D-02、D-05、D-40、D-46g

---

#### FR-004 系统管理员账号保护

**描述**：系统应保护系统管理员账号，禁止系统管理员之间的互相删除。

**验收标准**：

1. 系统管理员 A 尝试软删除系统管理员 B，返回 `PERMISSION_DENIED`，HTTP 403。
2. 系统中至少保留一个可用的系统管理员账号。
3. 系统管理员账号只能通过初始化脚本创建，不提供在线创建接口。

**关联决策**：D-05

---

### 2.2 借阅证管理模块

#### FR-005 办理借阅证

**描述**：系统应支持系统管理员为读者办理借阅证。借阅证号由系统自动生成，格式为 `CARD` + 4 位年份 + 6 位序号，序号按年递增。

**验收标准**：

1. 为无有效借阅证的读者办证，成功，返回借阅证号（如 `CARD2026000001`）、状态 `ACTIVE`。
2. 读者不存在，返回 404。
3. 该读者已存在有效借阅证（`ACTIVE` 或 `SUSPENDED`），返回 `CARD_ALREADY_EXISTS`，HTTP 409。
4. 借阅证号全局唯一，同年份内序号从 `000001` 开始递增。
5. 非系统管理员调用，返回 `PERMISSION_DENIED`，HTTP 403。

**关联决策**：D-06、D-07、D-05

---

#### FR-006 注销借阅证

**描述**：系统应支持系统管理员注销借阅证。注销为软删除，状态置为 `CANCELLED`，记录保留。

**验收标准**：

1. 注销有效借阅证，成功，状态变为 `CANCELLED`。
2. 注销后该读者不可再借书（见 BR-002）。
3. 注销操作记录经办系统管理员 ID 与时间。
4. 注销后该读者**可以重新办证**（`CANCELLED` 的证不占用 D-07 的一人一证限制）。

**关联决策**：D-07、D-09、D-10

---

#### FR-007 恢复已注销的借阅证

**描述**：系统应支持系统管理员将已注销的借阅证恢复为有效状态。

**验收标准**：

1. 恢复状态为 `CANCELLED` 的借阅证，成功，状态变为 `ACTIVE`。
2. 恢复时若该读者已有其他有效借阅证，返回 `CARD_ALREADY_EXISTS`，HTTP 409。
3. 恢复非 `CANCELLED` 状态的借阅证，返回 400 参数错误。
4. 非系统管理员调用，返回 403。

**关联决策**：D-10、D-07

---

#### FR-008 挂失与解挂借阅证

**描述**：系统应支持系统管理员将借阅证置为挂失（`SUSPENDED`）状态，以及从挂失状态恢复。

**验收标准**：

1. 将 `ACTIVE` 的证置为 `SUSPENDED`，成功。
2. `SUSPENDED` 状态的证不可借书（返回 `CARD_INVALID`）。
3. 将 `SUSPENDED` 的证恢复为 `ACTIVE`，成功。

**关联决策**：D-09

---

#### FR-009 查询借阅证信息

**描述**：系统应支持按借阅证号或读者查询借阅证信息。

**验收标准**：

1. 按借阅证号精确查询，返回证号、状态、所属读者、办证时间。
2. 按读者 ID 查询该读者的全部借阅证（含历史注销记录），**已注销的证仅系统管理员可见**。
3. 图书管理员查询时，结果中过滤掉 `CANCELLED` 状态的证。

**关联决策**：D-40、D-05

---

### 2.3 书目与馆藏管理模块

#### FR-010 添加图书标题信息

**描述**：系统应支持系统管理员添加图书标题（`BookTitle`）信息。

**验收标准**：

1. 提交题名、作者、类型（五种借出物类型之一），必填项完整则创建成功。
2. 可选字段：ISBN、出版社、出版年份、语种。
3. ISBN 若填写则须全局唯一，重复返回 409。
4. 借出物类型不在枚举内，返回 422。
5. 非系统管理员调用，返回 403。
6. 允许只创建标题而不添加任何副本（见 BR-014）。

**关联决策**：D-36、D-39、D-50

---

#### FR-011 删除图书标题信息

**描述**：系统应支持系统管理员软删除图书标题信息。

**验收标准**：

1. 删除标题，`is_deleted` 置为 `true`，记录保留。
2. 删除后该标题在读者与图书管理员的查询结果中**不可见**；系统管理员查询时可见。
3. 该标题下的所有副本同步置为 `REMOVED` 状态。
4. 若该标题下存在未归还的借阅记录，删除**不失败**；副本保持 `BORROWED` 直至归还，归还后置为 `REMOVED`。

**关联决策**：D-40、D-42、D-38

---

#### FR-012 添加馆藏副本

**描述**：系统应支持系统管理员为指定标题添加馆藏副本（`LibraryItem`）。

**验收标准**：

1. 为已存在的标题添加副本，需提供馆藏条码；条码格式 `BC` + 8 位数字。
2. 条码全局唯一，重复返回 409。
3. 新建副本默认状态为 `AVAILABLE`。
4. 可选字段：存放位置、入库日期、定价。
5. 指定标题不存在或已被软删除，返回 404。

**关联决策**：D-37、D-41、D-39

---

#### FR-013 删除馆藏副本

**描述**：系统应支持系统管理员软删除馆藏副本，以及标记副本为丢失或破损。

**验收标准**：

1. 删除副本，状态置为 `REMOVED`，记录保留。
2. 标记副本为 `LOST` 或 `DAMAGED`，成功。
3. `REMOVED`、`LOST`、`DAMAGED` 状态的副本均不可借（返回 `ITEM_NOT_AVAILABLE`）。
4. 状态为 `BORROWED` 的副本不允许直接删除，返回 400。
5. 已删除副本在读者与图书管理员查询中不可见，系统管理员可见。

**关联决策**：D-38、D-40、D-24

---

#### FR-014 查询图书

**描述**：系统应支持所有登录用户按条件检索图书标题及其馆藏可借情况。

**验收标准**：

1. 支持按题名模糊查询、按作者模糊查询、按 ISBN 精确查询、按借出物类型精确查询，条件可组合。
2. 支持"只看有可借副本"的筛选参数。
3. 查询结果显示每个标题的可借副本数量与总副本数量。
4. 查询结果**不包含**已软删除的标题与副本。
5. 结果支持分页，默认每页 20 条，最大 100 条。
6. 未登录用户调用，返回 401。

**关联决策**：D-43、D-46、D-40

---

### 2.4 借阅流通模块

#### FR-015 借书前置校验（预检查）

**描述**：系统应支持图书管理员在正式借出前，通过借阅证号预检查读者的借阅资格，返回读者信息与可借额度。

**验收标准**：

1. 输入借阅证号，返回读者姓名、读者类型、借阅额度、当前占用额度、剩余可借数量。
2. 同时返回是否存在超期未还记录、是否存在未缴罚款、是否存在即将到期记录。
3. 借阅证无效时，返回 `CARD_INVALID`，HTTP 400。
4. 非图书管理员调用，返回 403。
5. 本接口**不产生任何数据变更**（只读）。

**关联决策**：D-19、D-16

---

#### FR-016 办理借书

**描述**：系统应支持图书管理员代理读者办理借书，输入借阅证号与馆藏条码，创建借阅记录。

**验收标准**：

1. 全部校验通过时，创建借阅记录，`due_at` = 借出时刻 + 该读者类型的借阅天数，副本状态变为 `BORROWED`，记录经办图书管理员 ID，HTTP 201。
2. 依次校验 6 项条件，任一失败即拒绝（详见 BR-001 至 BR-006）：
   - 操作人具备图书管理员角色 → 否则 `PERMISSION_DENIED` 403
   - 借阅证存在且状态为 `ACTIVE` → 否则 `CARD_INVALID` 400
   - 未超出最大借阅数量 → 否则 `BORROW_LIMIT_EXCEEDED` 400
   - 不存在超期未还的借阅记录 → 否则 `OVERDUE_LOAN_EXISTS` 400
   - 不存在未缴清的罚款 → 否则 `UNPAID_FINE_EXISTS` 400
   - 馆藏副本存在、属本馆、状态为 `AVAILABLE` → 否则 `ITEM_NOT_AVAILABLE` 400
3. 整个操作在单个事务内完成，任一步失败全部回滚。
4. 允许同一读者借阅同一标题的多个副本。
5. 读者可以自行借书（不允许）；读者调用返回 403。

**关联决策**：D-16、D-13、D-14、D-17、D-18、D-21、D-46c

---

#### FR-017 办理还书

**描述**：系统应支持图书管理员凭馆藏条码办理还书，无需借阅证。

**验收标准**：

1. 输入馆藏条码，找到该副本未归还的借阅记录，设置 `returned_at`，状态置为 `RETURNED`。
2. 副本状态变更：该标题无人预约 → `AVAILABLE`；有人预约排队 → `RESERVED`。
3. 若已超期，按 BR-010 计算罚款并生成 `FineRecord`（状态 `UNPAID`）。
4. 馆藏条码不存在或不属于本馆，返回 `ITEM_NOT_FOUND`，HTTP 404。
5. 该副本无未归还的借阅记录，返回 `LOAN_NOT_FOUND`，HTTP 404。
6. 记录经办图书管理员 ID。
7. 整个操作在单个事务内完成。

**关联决策**：D-20、D-22、D-26、D-27、D-46c

---

#### FR-018 续借图书

**描述**：系统应支持读者续借本人已借出的图书，最多续借 2 次，每次延长 7 天。

**验收标准**：

1. 读者对本人名下未超期的借阅记录发起续借，`due_at` 增加 7 天，续借次数 +1。
2. 已续借 2 次的记录，再次续借返回 `RENEW_LIMIT_EXCEEDED`，HTTP 400。
3. 已超期的记录，续借返回 `RENEW_OVERDUE`，HTTP 400。
4. 读者当前占用额度已超出最大借阅数量时，禁止续借。
5. 读者尝试续借他人名下的记录，返回 403。
6. 续借不额外占用借阅额度。
7. 存在预约排队**不影响**续借资格。

**关联决策**：D-15、D-13

---

#### FR-019 查询借阅信息

**描述**：系统应支持查询借阅信息，读者仅可查询本人，图书管理员与系统管理员可查询任意读者。

**验收标准**：

1. 返回当前借阅列表：书名、条码、借出时间、到期时间、剩余天数、是否超期、是否可续借、已续借次数。
2. 返回历史借阅记录。
3. 返回预约列表：标题、状态、排队位置。
4. 返回罚款记录：金额、缴纳状态、产生时间。
5. 读者查询他人借阅信息，返回 `PERMISSION_DENIED`，HTTP 403。
6. 读者查询界面中不展示经办图书管理员 ID（内部审计字段）。

**关联决策**：D-44、D-45

---

#### FR-020 到期提醒

**描述**：读者登录成功后，系统应一次性提示其即将到期（3 天内）与已超期的借阅记录。

**验收标准**：

1. 读者登录成功后，若存在 3 天内到期或已超期的借阅记录，返回告警列表。
2. 同一会话内不重复提醒（前端以 Dialog 集中展示一次，可关闭）。
3. 无即将到期或超期记录时，不返回告警。
4. 图书管理员与系统管理员登录时不触发此提醒。

**关联决策**：D-44、D-23

### 2.5 预约管理模块

#### FR-021 预约图书

**描述**：系统应支持读者预约无副本可借的图书标题，按创建时间排队，队列上限 5 人。

**验收标准**：

1. 该标题下**所有副本均不可借**时，读者可发起预约，成功创建预约记录，状态 `ACTIVE`。
2. 该标题下存在任一 `AVAILABLE` 副本时，预约失败，返回 `ITEM_AVAILABLE_NO_RESERVATION`，HTTP 400。
3. 该读者对该标题已有有效预约（`ACTIVE` 或 `READY`），重复预约失败，返回 `DUPLICATE_RESERVATION`，HTTP 409。
4. 该标题的预约队列已达 5 人，返回 `RESERVATION_QUEUE_FULL`，HTTP 409。
5. 读者无有效借阅证，返回 `CARD_REQUIRED`，HTTP 400。
6. 读者不存在或已被软删除，返回 404；标题不存在或已被软删除，返回 404。
7. 预约创建后占用 1 个借阅额度。

**关联决策**：D-29、D-30、D-31、D-35、D-11、D-13

---

#### FR-022 取消预约

**描述**：系统应支持读者取消本人的有效预约。

**验收标准**：

1. 读者取消本人 `ACTIVE` 或 `READY` 状态的预约，状态置为 `CANCELLED`，释放占用的借阅额度。
2. 取消后队列自动顺延，后续读者排队位置前移。
3. 读者取消他人预约，返回 403。
4. 取消失效（`EXPIRED`）或已取消（`CANCELLED`）的预约，返回 400。

**关联决策**：D-34、D-30

---

#### FR-023 预约到书与失效处理

**描述**：系统应在还书触发预约预留后标记预约可借取，并在读者 7 天内未取书时自动失效。

**验收标准**：

1. 还书时若该标题存在有效预约队列，副本状态置为 `RESERVED`，队首读者的预约状态由 `ACTIVE` 变为 `READY`。
2. 预约自创建起 7 天内未借到书，状态置为 `EXPIRED`，释放借阅额度，队列顺延。
3. `READY` 状态的预约在标记后 7 天内未被借走，状态置为 `EXPIRED`，副本释放为 `AVAILABLE` 或转给下一位预约者。
4. 失效处理由定时任务或查询时惰性判定实现。

**关联决策**：D-32、D-33

---

#### FR-024 查询预约状态

**描述**：系统应支持读者查询本人预约的排队位置与状态。

**验收标准**：

1. 返回预约列表：标题、预约时间、当前状态（`ACTIVE`/`READY`/`EXPIRED`/`CANCELLED`）、队列位置。
2. 队列位置按 `created_at` 升序计算，从 1 开始。
3. 读者只能查询本人的预约。

**关联决策**：D-30、D-45

### 2.6 罚款管理模块

#### FR-025 罚款计算

**描述**：系统应在还书时按借出物类型计算超期罚款，含 2 天宽限期，单笔封顶 100 元。

**验收标准**：

1. 逾期 0-2 天，罚款为 0。
2. 逾期 N 天（N ≥ 3），罚款 = min((N - 2) × 单价, 100)。
3. 单价按借出物类型从 `fine_rules` 表读取（中文图书 0.20、外文图书 0.50、中文杂志 0.10、外文杂志 0.20、论文 1.00 元/天）。
4. 计算结果精确到分（两位小数）。
5. 逾期天数按 `returned_at - due_at` 精确到秒计算，不足一天按一天计。

**关联决策**：D-25、D-26、D-14、D-47a

#### FR-026 罚款记录查询与缴纳

**描述**：系统应支持查询罚款记录，并支持图书管理员或系统管理员标记罚款已缴纳。

**验收标准**：

1. 读者可查询本人的罚款记录（金额、状态、产生时间），但**不可修改**。
2. 图书管理员可查询任意读者的罚款记录并标记为 `PAID`，记录经办人 ID 与时间。
3. 系统管理员具备相同权限。
4. 已缴纳的罚款不可重复标记，返回 400。
5. 缴纳方式为线下，系统仅记录状态。

**关联决策**：D-27、D-28、D-45、D-46g

### 2.7 规则维护模块

#### FR-027 维护借阅规则

**描述**：系统应支持系统管理员查询与修改各读者类型的借阅规则（最大借阅数量、借阅期限）。

**验收标准**：

1. 查询借阅规则，返回全部读者类型的额度与期限。
2. 修改某读者类型的额度或期限，成功，即时生效。
3. 修改**不影响**已存在的借阅记录（`due_at` 在借阅时已快照）。
4. 最大借阅数量必须为正整数，借阅期限必须为正整数，否则返回 422。
5. 非系统管理员调用，返回 403。
6. 修改操作记录经办人 ID、时间、变更前后值。

**关联决策**：D-47a、D-46g

#### FR-028 维护罚款规则

**描述**：系统应支持系统管理员查询与修改罚款规则（各借出物类型单价、宽限期天数、单笔封顶金额）。

**验收标准**：

1. 查询罚款规则，返回五种借出物类型的单价、宽限期天数、封顶金额。
2. 修改单价、宽限期或封顶金额，成功，即时生效。
3. 修改**不影响**已生成的罚款记录。
4. 单价必须为非负数，宽限期与封顶必须为非负整数，否则返回 422。
5. 非系统管理员调用，返回 403。
6. 修改操作记录经办人 ID、时间、变更前后值。

**关联决策**：D-47a、D-46g

## 3. 业务规则（Business Rules）

> 共 53 条业务规则（`BR-001` ~ `BR-050`，另有 3 条后缀编号 `BR-024a`、`BR-025a`、`BR-025b`）。业务规则是实现时必须遵守的约束，不得写入表现层（见 `constitution.md` 第八条）。
> 编号规则：`BR-XXX`。

### 3.1 借阅证规则

| 编号 | 规则 |
|---|---|
| **BR-001** | 借书时必须校验借阅证存在且状态为 `ACTIVE`，否则拒绝。 |
| **BR-002** | 借阅证状态为 `SUSPENDED`、`CANCELLED`、`EXPIRED` 时均不可借书。 |
| **BR-003** | 一名读者最多拥有一张有效借阅证（`ACTIVE` 或 `SUSPENDED`）；`CANCELLED` 的证不计入。 |
| **BR-004** | 借阅证号格式为 `CARD` + 4 位年份 + 6 位序号，全局唯一，序号按年递增。 |
| **BR-005** | 借阅证不设过期时间。系统保留 `expired_at` 字段但当前不校验。 |

### 3.2 借阅规则

| 编号 | 规则 |
|---|---|
| **BR-006** | 各读者类型的借阅额度与期限如下：专科生 5 册/30 天；本科生 5 册/30 天；研究生 10 册/60 天；博士生 15 册/90 天；教师 20 册/90 天。 |
| **BR-007** | 借阅额度占用 = 未归还的借阅记录数（`BORROWED` + `OVERDUE`）+ 有效预约数（`ACTIVE` + `READY`）。 |
| **BR-008** | 占用额度 ≥ 最大借阅数量时，禁止借书与预约。 |
| **BR-009** | 借阅期限自借出时刻起算，`due_at` = `borrowed_at` + 借阅天数。到期时刻之前归还算按期。 |
| **BR-010** | 存在任何超期未还的借阅记录时，禁止借书。 |
| **BR-011** | 存在任何未缴清（`UNPAID`）的罚款记录时，禁止借书。 |
| **BR-012** | 未办理借阅证或借阅证已失效的读者，不具备借阅资格，不可借书与预约。 |
| **BR-013** | 允许同一读者借阅同一图书标题的多个副本。 |
| **BR-014** | 允许图书标题在无任何馆藏副本的状态下存在；此状态下不可借阅但可被检索。 |

### 3.3 续借规则

| 编号 | 规则 |
|---|---|
| **BR-015** | 每条借阅记录最多续借 2 次，每次延长 7 天，与读者类型无关。 |
| **BR-016** | 已超期的借阅记录不可续借。 |
| **BR-017** | 读者当前占用额度超出最大借阅数量时，不可续借。 |
| **BR-018** | 存在预约排队不构成禁止续借的条件。 |
| **BR-019** | 续借不额外占用借阅额度；归还后重新借阅，续借次数重置。 |

### 3.4 预约规则

| 编号 | 规则 |
|---|---|
| **BR-020** | 仅当图书标题下**所有副本均不可借**时，才允许预约。 |
| **BR-021** | 预约按 `created_at` 升序排队，先到先得。 |
| **BR-022** | 每个图书标题的预约队列上限为 5 人，满员后拒绝新预约。 |
| **BR-023** | 同一读者对同一图书标题不得存在多个有效预约（`ACTIVE` 或 `READY`）。 |
| **BR-024** | 还书时若该标题存在有效预约队列，副本置为 `RESERVED`，不进入可借状态。 |
| **BR-025** | 预约自创建起 7 天内有效；`READY` 状态自标记起 7 天内有效。超期未取则失效，队列顺延。 |
| **BR-026** | 预约占用 1 个借阅额度；预约取消或失效后立即释放。 |
| **BR-024a** | `RESERVED` 副本的归属**始终跟随队列头部的有效预约**。队首预约失效或取消时，副本转交给队列中的下一位有效预约（其状态由 `ACTIVE` 置为 `READY`，副本保持 `RESERVED`）；若队列已无有效预约，副本才释放为 `AVAILABLE`。 |
| **BR-025a** | 有效预约（`ACTIVE` 或 `READY`）**均可由读者主动取消**（UC-006）。取消后立即从队列移除并释放其占用的借阅额度；若取消的是 `READY` 预约，副本按 BR-024a 转交。 |
| **BR-025b** | 预约超期采用**惰性判定**（在查询或操作时计算，不引入定时任务，见待确认问题 Q-01）。但一旦判定某预约已超期，**必须在同一次操作内**完成队列顺延与副本交接（BR-024a），不得只标记失效而遗留 `RESERVED` 副本无人接管。 |

### 3.5 罚款规则

| 编号 | 规则 |
|---|---|
| **BR-027** | 罚款 = min(max(逾期天数 - 宽限期天数, 0) × 该借出物类型单价, 单笔封顶金额)。默认宽限期 2 天，封顶 100 元。 |
| **BR-028** | 罚款单价：中文图书 0.20、外文图书 0.50、中文杂志 0.10、外文杂志 0.20、论文 1.00（元/天）。 |
| **BR-029** | 罚款在还书时一次性计算并生成记录，初始状态 `UNPAID`。超期期间不预生成。 |
| **BR-030** | 单笔罚款封顶 100 元，各笔独立计算，不合并封顶。 |
| **BR-031** | 罚款由图书管理员或系统管理员线下收取并标记为 `PAID`，系统不接入支付。 |

### 3.6 馆藏状态规则

| 编号 | 规则 |
|---|---|
| **BR-032** | 馆藏副本状态共 6 种：`AVAILABLE`、`BORROWED`、`RESERVED`、`LOST`、`DAMAGED`、`REMOVED`。 |
| **BR-033** | 仅 `AVAILABLE` 状态的副本可被借出。 |
| **BR-034** | `BORROWED` 状态的副本不可直接删除，须先归还。 |
| **BR-035** | 借出物类型共 5 种：`CHINESE_BOOK`、`FOREIGN_BOOK`、`CHINESE_MAGAZINE`、`FOREIGN_MAGAZINE`、`THESIS`。 |

### 3.7 数据可见性规则

| 编号 | 规则 |
|---|---|
| **BR-036** | 所有删除均为软删除，记录永久保留。 |
| **BR-037** | 已软删除的记录（借阅证、图书标题、馆藏副本）**仅系统管理员可见**；读者与图书管理员的查询结果中必须过滤。 |
| **BR-038** | 借阅记录、罚款记录永久保留，不自动清理。 |
| **BR-039** | 读者只能访问本人的数据，服务端必须校验资源归属，不得信任请求参数中的 `reader_id`。 |

### 3.8 权限规则

| 编号 | 规则 |
|---|---|
| **BR-040** | 借书、还书、收缴罚款必须由图书管理员或系统管理员执行；读者无此权限。 |
| **BR-041** | 借阅证管理、账号管理、书目管理、馆藏管理、规则维护必须由系统管理员执行；图书管理员无此权限。 |

| **BR-043** | 系统管理员之间不可互相删除。 |
| **BR-044** | 一名自然人可拥有多个账号，但每个角色最多一个账号；一个账号只持有一个角色。 |

### 3.9 认证规则

| 编号 | 规则 |
|---|---|
