# 测试计划（Test Plan）

> **文档编号**：`specs/15-test-plan.md`
> **制定依据**：`02-requirements.md`、`03-use-cases.md`、`09-design-model.md`、`14-api-spec.md`
> **版本**：v1.0
> **日期**：2026-09-20
>
> **测试框架**：`pytest` + `httpx`（FastAPI `TestClient` / `ASGITransport`）
> **数据库**：SQLite 内存库（每个测试用例独立事务或独立库，保证可重复运行）
> **运行命令**：`cd backend && pytest -v`

## 1. 测试策略

### 1.1 测试分层

| 层级 | 目录 | 范围 | 依赖 | 数量 |
|---|---|---|---|:---:|
| **单元测试** | `backend/tests/unit/` | 领域层：值对象、实体行为、领域服务、策略对象 | **不依赖数据库、不依赖 Web 框架** | 14 |
| **集成测试** | `backend/tests/integration/` | API 端到端：路由 → 应用服务 → 领域 → 持久化 | 内存 SQLite + TestClient | 22 |
| | | | **合计** | **36** |

**单元测试的硬约束**（宪法第五条、`08-package-diagram.md` R-3）：`tests/unit/` 下**不得出现** `fastapi`、`sqlalchemy`、`Session` 等导入。若领域层单测需要连数据库，即说明分层被破坏。

## 2. 单元测试用例（`tests/unit/`）

### TC-020 宽限期内还书罚款为 0

| 项 | 内容 |
|---|---|
| **测试目标** | 验证 `FineRule.billed_days` 与 `calculate_fine` 正确处理宽限期（默认 2 天，BR-027） |
| **前置条件** | 构造 `FineRule(item_type=FOREIGN_BOOK, daily_price=0.50, grace_days=2, max_amount=100.00)` |
| **输入** | `overdue_days` ∈ {0, 1, 2, 3, 5} |
| **操作步骤** | 1. 调用 `billed_days(overdue_days)`；2. 调用 `calculate_fine(item_type, overdue_days)` |
| **预期结果** | 0→0 天/0.00 元；1→0 天/0.00 元；2→0 天/0.00 元；3→1 天/0.50 元；5→3 天/1.50 元 |

### TC-021 罚款封顶生效

| 项 | 内容 |
|---|---|
| **测试目标** | 验证单笔罚款不超过 `max_amount`，且金额精度为 2 位小数 |
| **前置条件** | `FineRule(item_type=THESIS, daily_price=1.00, grace_days=2, max_amount=100.00)` |
| **输入** | `overdue_days` = 365（计罚 363 天，理论金额 363.00 元） |
| **操作步骤** | 调用 `calculate_fine`，检查返回的 `Money` 值 |
| **预期结果** | 金额为 `100.00`（封顶生效）；类型为 `Decimal` 而非 `float`；**无浮点误差**（如 `0.20 × 3` 必须为 `0.60` 而非 `0.6000000000000001`） |

### TC-020b 值对象与实体行为（单元测试组）

| 项 | 内容 |
|---|---|
| **测试目标** | 验证领域层核心行为，**不连数据库** |
| **前置条件** | 无（纯内存对象） |
| **输入** | 构造 `BorrowCard`、`CardNumber`、`Barcode`、`Isbn`、`DateRange`、`Loan`、`Money` 等对象 |
| **操作步骤** | 1. `CardNumber.is_valid` 校验 `CARD2026000001` 合法、`CARD999` 非法；2. `Barcode.generate` 生成 10 位条码；3. `Isbn.is_valid` 校验 ISBN-10/13；4. `DateRange.extend_days(7)` 返回**新对象**且原对象不变；5. `Loan.overdue_days` 与实际超期天数一致；6. `BorrowCard` 状态机拒绝非法流转（如 `CANCELLED` 直接 → `SUSPENDED`）；7. `BorrowEligibilityService.check_quota` 对 5 种读者类型返回正确额度判定 |
| **预期结果** | 全部断言通过；**`tests/unit/` 下无 `fastapi` / `sqlalchemy` 导入** |

## 3. 集成测试用例（`tests/integration/`）

### TC-001 注册读者成功

| 项 | 内容 |
|---|---|
| **测试目标** | 读者可自助注册，注册后立即可登录但不具备借阅资格 |
| **前置条件** | 空数据库；系统已初始化读者类型枚举 |
| **输入** | `{"username": "reader001", "password": "pass1234", "name": "张三", "department": "计算机学院", "reader_type": "UNDERGRADUATE"}` |
| **操作步骤** | 1. `POST /api/auth/register`；2. 用同一凭据 `POST /api/auth/login`；3. 尝试调用 `POST /api/circulation/precheck` |
| **预期结果** | 步骤 1 返回 201 与账号 ID；步骤 2 返回 200 与 Token；步骤 3 返回 403 `PERMISSION_DENIED`（读者无借书权限，且未办证） |

### TC-002 注册读者用户名重复失败

| 项 | 内容 |
|---|---|

| 项 | 内容 |
